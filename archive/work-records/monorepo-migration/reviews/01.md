## Findings

### M1 Material: candidate-schema reference documents the old `copy` contract
Anchor: docs/reference/candidate-schema.md:10-29 and :62-83
Scenario: a developer follows new-cv step 1-2 and this page. Expected: `copy` is Flagship input, merged over adapter defaults, not a candidate fact. Actual: the top-level example lists `copy` inside the candidate record, and lines 82-83 say "When `copy` is given it replaces the whole dictionary, so include every key you still want" - the opposite of adapter.typ:18 and of flagship-input.schema.json's own description; a record built this way fails the facts schema the skill tells them to validate against. Impact: the contract this card exists to separate is documented wrongly at its reference page. Fix: drop `copy` from the facts example; add a short "Flagship input" subsection: defaults live in templates/flagship/adapter/adapter.typ, overrides merge (only changed keys), pass via `flagship(copy: ...)` or, legacy, inside the record which then validates only against flagship-input.schema.json.
