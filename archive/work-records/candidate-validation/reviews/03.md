## Findings

### R3-01 Minor: the docs say every problem is listed, but the refusal stops at ten
Anchor: `docs/reference/candidate-schema.md:117`, `docs/guides/build-a-cv.md:110`, `packages/cv-workflow/README.md:55`; `validate.py:13,72-73`.
Scenario: a record with twelve bad `months` values. Expected per the docs: twelve lines. Actual: ten lines plus `  ... and 2 more`. Impact: low, because the count is shown and a re-render lists the rest. Fix: reword to "lists the offending fields with their paths (the first ten, then a count)". Optionally assert the count line; no test covers it today.

### R3-02 Minor: a broken example record fails the suite under the wrong file name
Anchor: `tests/run.py:33-35`, `validate.py:74`.
Scenario: an example record gains a misspelt key. Actual: the suite stops with `WorkflowError: candidate.json does not match …`. It names neither the entry point nor the `…-example.json` file, and the "Read the result" section of the `verify-cv` skill has no line for this failure. Fix: in `check_example_records`, catch `WorkflowError` and raise `AssertionError((entry.name, path, str(error)))`. Add one line to the skill.

### R3-03 Minor: the new-cv skill still treats the check as optional
Anchor: `.claude/skills/new-cv/SKILL.md:27-28`.
Step 2 says to validate against the facts schema "if a validator is available; otherwise rely on the compile-time assertions". Render now always checks against the Flagship input schema and needs `jsonschema`, and the suite checks the example records. Fix: point step 2 at those checks.

### R3-04 Minor: the stored reports 01 and 02 are condensed, not the reports as returned

Fix: restore the returned texts if they are still available. Otherwise add one header line to each file: "condensed by the lead; original not retained". Store this report unchanged.
