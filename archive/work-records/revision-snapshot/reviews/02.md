## Findings
### R2-m1 Minor: `include` is now found only at a statement start; expression positions round 1 found are missed
Anchor: `packages/cv-workflow/cv_workflow/render.py:17-18`
- **Scenario (in-memory probe, 8a1edcf against 6ad23e2):** these return `[]` now, but round 1 found them:
  - `#grid(columns: 2, include "left.typ", include "right.typ")`
  - `it => include "h.typ"`
  - `(left: include "l.typ")`
  - `return include "r.typ"`
  - `+ include "…"` (by reading the regex)
- **Remaining prose false positives:** a wrapped markup line that starts `include "Athens by Night"`, and `(include "…")`.
- **Expected:** a literal `include` is copied. The README lists `include` among the reads that render finds, and build-a-cv.md implies that only computed paths fail.
- **Actual:** the file is not copied. The snapshot compile fails with Typst's "file not found … revisions/<id>/inputs/left.typ", and the revision is kept as failed. There is no live read and nothing becomes approvable.
- **Impact:** low. It is a loud failure, but its message is confusing, and it hits a plausible two-column idiom.
- **Fix:** add `,`, `:`, `+` and `>` to the statement-start class, accepting rarer prose hits, and add one line to ONE_OFF (for example `#grid(columns: 1, include "parts/a.typ")`). Alternatively, state the narrower rule in the README.
