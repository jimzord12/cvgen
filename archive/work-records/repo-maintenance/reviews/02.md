## Findings

### R2-01 Minor: two pre-approved commands can still execute or write
Anchor: `.claude/skills/repo-maintenance/SKILL.md:5`; `audit.py:143` (`--since`)
- **`git grep*`:** this pre-approval still allows `git grep -O<cmd>` (`--open-files-in-pager`), which runs any program. The bundle's own guard lists `git grep -Oless foo` as a command to block (`tests/repo_maintenance.py`, section 4).
- **`--since`:** the pinned script passes the `--since` value straight into `git diff --name-only <ref>...HEAD`. With `--since=--output=x`, git writes the file `x...HEAD` into the repo root.
- **Impact:** both need the agent to issue the argument, for example after reading a prompt-injected doc. That is the same class as R1-03, and the review of the R1-03 fix found it.
- **Fix:** drop `Bash(git grep*)` from the pre-approvals (the `apply` step's git grep calls will then ask for approval, which is fine). In audit.py, reject a `--since` value that starts with `-`, or put `--end-of-options` before it.

### R2-02 Minor: the parser trap that broke allow_names is still there for every list key
Anchor: `audit.py:73-95` (`clean_item`, `load_config`)
- **Scenario:** a future edit writes `protected:   # frozen things` on the key line.
- **Actual:** `clean_item` only strips a comment that has whitespace before `#`. So the key's value becomes the string `"# frozen things"`, the list items below it are dropped, and nothing is protected. No error appears.
- **Coverage:** today the tests would catch this only for `allow_names`, and for `protected` only indirectly.
- **Fix:** in `load_config`, treat a value that starts with `#` as empty. Add one fixture line with a key-line comment.

### N1 Note: the adapter's Git paragraph calls a floor item a "generic default"
In the adapter's "`apply` in CVgen's Git" paragraph, the branch name is described as one of "the skill's generic defaults". SKILL.md:117 puts `maintenance/<date>-<slug>` under the heading "nothing overrides this". What the floor protects is "a non-default branch", and `chore/maintenance-<topic>` still meets it. Suggested wording: "the floor's branch rule holds; only the name follows CVgen." The merge after the gate is consistent with SKILL.md step 8.

`docs/proposals/repo-maintenance.md`, section "Changes made to the bundle", does not mention the narrowed `allowed-tools`. SKILL.md is therefore no longer byte-identical to the bundle, but the record does not say so.

SKILL.md:76 says "Run `scripts/audit.py`", a path relative to the skill folder. An agent that runs the script from the skill folder or by absolute path gets a permission prompt. That is friction, not a safety problem.
