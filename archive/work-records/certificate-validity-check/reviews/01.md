## Findings
### F1 Material: the "not date-checked" count never reaches the command output
Anchor: `render.py:99`, `__init__.py:27-28`; proposal step 3 and its Decisions entry ("everything else as written ... count of unchecked dates")
- **Scenario:** in my rerun, the first render of the fictional engineer record wrote `date_checked: 4, not_date_checked: 4` to checks.json. Stdout showed only `"warnings": []` and stderr was empty. A client record whose dates are typed `Oct 2026` or `2026-10-14` produces the same silent output, although nothing was checked. `status` also shows the same `warnings: []` for three different cases: a clean check, a record where every date is free text, and a revision rendered before this change.
- **Expected:** the proposal says "the output says how many certificates were not date-checked, so silence is never mistaken for a pass".
- **Actual:** the count and `reference_date` exist only in checks.json.
- **Impact:** the first risk the proposal lists (other date formats silently skipped) stays unmitigated for anyone reading the command output. An expired date written in another format goes out unflagged.
- **Smallest fix:** return `date_checked`, `not_date_checked` and `reference_date` in the render summary and per revision in `status` (`null` when the block is absent). Print one stderr line when `not_date_checked > 0`. Assert both in step 9.
- If the lead reads "the output" as meaning checks.json, the next reviewer should settle it. The purpose clause supports my reading.

### F2 Minor: `status` crashes with a traceback on a wrong-shape `certificates` block
Anchor: `__init__.py:27`, `scripts/cv.py:29`
- **Scenario:** I ran the real CLI on a copy of the workspace under builds/. `certificates: "x"` or `["x"]` raises `AttributeError`. `warnings: null` raises `TypeError` in `warn()`. Each exits 1 with no listing for any revision.
- **Expected vs actual:** the pdf-workflow N4 rule says a wrong JSON shape is never a traceback. This change breaks it; on `main`, `status` never read this block.
- **Smallest fix:** accept the block only if it is a dict whose `warnings` is a list of strings, otherwise use `[]`. Add one assertion in step 7.

### N1 Note: `sys.stderr.reconfigure(errors='backslashreplace')` does nothing
CPython's stderr already uses `backslashreplace`. On a cp1252 pipe with PYTHONIOENCODING removed, a Greek title prints as `\u0399...` and exits 0, with or without the line (probe). The comment's claim that it prevents a crash is inaccurate. The call would also raise `AttributeError` if an in-process caller swapped stderr for a StringIO. Remove the line or correct the comment.

### N2 Note: a non-list `certificates` raises `TypeError`
This can only happen when no schema applies (an entry that imports only the Framework). The result is a traceback: `render.json` exists but `checks.json` does not. Approval is then refused, so it fails safe. An `isinstance(list)` guard would fix it.

### N3 Note: glossary and wording
`Certificate Warning` is a candidate glossary term. The warning text says "1 days".
