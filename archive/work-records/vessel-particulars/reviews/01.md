### M1 Material: the "no row moves" check compares component names, not vessel rows
Anchor: C:\Users\jimzord12\Documents\GitHub\cvgen\tests\run.py:254 (list reassigned at :192)
Scenario: `names` holds the vessel names and ranks at line 157. Line 192 reassigns it to the 31 contract-fixture component names (`label`, `rule`, `vessel-row`…), and line 254 loops over that second list.
Expected: the y0 of every vessel name and rank is compared between engineer.pdf and particulars.pdf.
Actual: only "portrait" (hero) and "rule" (a page-2 certificate line) match anything; every other comparison is `[] == []`. A particulars row that grows and pushes later page-1 rows down still passes. Page 1 has about 89 pt of slack before the overflow check would fire.
Impact: the acceptance criterion "no row moves" has no working guard. Behaviour is correct today: using the intended list I found no moved name or rank, and no moved word on either page above page 2's education block, in both the author's and my PDFs.
Fix: give the vessel list its own variable (lines 157, 160 and 254), and assert that each search finds something so the check cannot go vacuous again.
