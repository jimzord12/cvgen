## 6. Conflicts and gaps

1. **`Intake Form` "instead of" vs "beside".** Atlas says the form is "instead" (A:92 "Optional: a designed Google `Intake Form` instead"; A:116 "(or run the form script ... and send the link)"). The owner's decision says "beside the `Relay` message, never instead of it" (PC:173-177), and the guide says "Beside the chat message" (G:91-92).
2. **Stall rule differs.** Guide: a client "who never reaches `Export`" is named "once three months pass without progress since the intake date" (G:300-302). Skill: "any client with no `Export` three months after intake" (S:95-97); Atlas the same (A:43). "Without progress" and "no `Export`" give different answers for a client still actively in research at month 3.
3. **`status=sent` is stamped before the draft is sent.** Compile and stamp `status=sent` happen together (G:258-261; S:62-63), but sending is a later owner act (G:272-274; A:323). The schema has no status for "compiled, not sent" (OS:38-39). The SHA-256 written to README "when the owner sends it" (G:272-274) duplicates the `sha256` the `Meta File` already holds (OW:133).
4. **Placeholder for the `Envelope` folder.** The real folder is `private/<name>-<rank>/` (G:31-36; S:13; BC:12-14; NC:19-20), which is client data (G:63). Other sources call it `private/<envelope>/` (A:65, A:307; GL:47; PW:128), `private/<candidate>/` (PW:72) or here `private/<alias>/`. The Design Review app groups and labels drafts by that folder name and the candidate's name (`scripts/design_review/server.py`:69-72), which is fine locally. A typed model has to choose one placeholder.
5. **`Alias` numbering is unspecified and the pattern differs.** Docs say `client-<yyyy>-<mm>-<nn>` (G:64; S:15; GL:48). The schema also allows a suffix `(-\d+)?` (OS:13), and the error text says `client-YYYY-MM-NN` (OW:61, OW:72). Nothing says how `<nn>` is chosen (per month? global?) or how collisions are checked. Within stages 1-4 no code checks it until the first stamp.
6. **"Text draft" names two different things in the `Meta File`.** The glossary's `Text Draft` (the client's PDF, GL:57) is `kind: client-draft` (OS:10, OS:38-39; PW:128). `kind: text-draft` is a design-concept direction of the house design (OS:32-33; PW:126). That is one word for two things, which glossary rule 3 forbids (GL:17-20).
7. **Who files the `Sign-off` screenshot.** In G's table the owner "saves the client's OK" (G:26), and Atlas has the owner save `draft/sign-off-NN.png` (A:323).
