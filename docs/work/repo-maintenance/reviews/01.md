## Findings

### R1-01 Material: `allow_names` never matches, so the Session Sweep reports a false Medium every time and lists the Frozen Reference for renaming
Anchor: `.claude/repo-maintenance.md:63-65`; `audit.py:36-56`, `:216-225`
- Scenario: `glob_re` passes `[` through `re.escape`, so `[0-9]` becomes a literal string.
- Actual: my `--mode quick` run at d71d5af still reports `[Medium] N2` for `flagship-v11.typ` and `Marine-Engineer-CV-v11.pdf`. It is tier B ("propose a descriptive name") because the layout file is not protected (`audit.py:181`). This is one of the lead's "Medium 2". It will reappear in every Session Sweep.
- Expected: those two versioned names are suppressed, as the adapter says.
- Fix: use `"**/tests/approved/*-v??.pdf"` and `"**/layouts/flagship-v??.typ"` (`?` is supported). In section 2 of `tests/repo_maintenance.py`, rename the fixture `ref.pdf` to `...-v11.pdf` and assert N2 is absent. Today the test does not cover `allow_names` at all.

### R1-02 Minor: `git_ignored` only checks the first path segment
Anchor: `audit.py:163-169`
- `private/x/cv.pdf`, `builds/…` and `.local/…` are handled correctly.
- `private/<name>/cv.pdf` never reaches the check, because the token regex at `:373` rejects `<`.
- `.night-shift/` counts as ignored (`.gitignore:31`, `.night-shift/*`), so a dead mention under the tracked `.night-shift/history/` is hidden.
- A nested ignored path such as `packages/cv-workflow/__pycache__/…` is still reported as dead.
- The cache is a mutable default keyed without the repo root. That is safe only because each process audits one repo.
- Fix: check the full token (batch with `--stdin`), keep the cache on `self`, and add a negated-subfolder fixture.

### R1-03 Minor: the skill's pre-approved commands are wider than its safety floor
Anchor: `SKILL.md:5`
- `Bash(git diff*)` and `Bash(git log*)` allow `--output=<file>`, which writes a file. The bundle's own guard test blocks exactly this case (`tests/repo_maintenance.py:187`).
- `Bash(python *scripts/audit.py*)` also matches `python -c "<anything>" scripts/audit.py`.
- The guard was not adopted, so nothing else narrows these patterns.
- Fix: pin the full script path (`Bash(python .claude/skills/repo-maintenance/scripts/audit.py *)`, same for `py`/`python3`), and either drop `git diff`/`git log` from the pre-approvals or record that the risk is accepted.

### R1-04 Minor: the adapter does not reconcile `apply` with CVgen's Git rules
Anchor: `SKILL.md:115-129` against `docs/git-workflow.md:30`, `docs/conventions.md:124-133`
- The branch name `maintenance/<date>-<slug>` is in the floor ("nothing overrides this"). git-workflow prefers `<type>/<topic>`.
- The commit type `move:` is not in the conventions list.
- "Do not merge" says nothing about the agent-owned merge after a PASS.
- Step 1 writes the baseline JSON "outside the repo", but the floor says "Never write outside the repo root".
- The skill's precedence rule says to stop on a conflict, so the first `apply` stalls or improvises.
- Fix: one adapter paragraph setting the CVgen branch and commit form, the baseline location (a new `builds/repo-health-<ts>/`), and integration per git-workflow after the review gate.

### R1-05 Minor: `ignore` removes the dated records from every check, not only the link checks
Anchor: adapter `:27-32`; `audit.py:172`, `:511-544`
Untracked, secret-named, oversized and generated files under `docs/work/**` are no longer reported. The adapter comment implies only link and wording checks are affected. Fix: state this tradeoff in the comment, or defer a per-check ignore.
