### m2 Minor: the heal re-stamp downgrades a delivered CV to `approved`
Anchor: `approve.py:28`
Scenario: the owner sends the PDF and it is stamped `status=delivered` (build-a-cv §6). Later the same `cv.py approve` command is rerun, for example pasted again from history.
Expected: the Meta File stays `delivered`.
Actual: `stamp` merges `{'status': 'approved'}` over the earlier Meta File, so the `Design Review` app shows a delivered CV as merely approved. Before this fix the early return touched nothing.
Fix: heal only when the current status is not already `approved` or `delivered`.

### m3 Minor: lang normalisation still lets a non-ASCII value reach the schema after the compile
Anchor: `render.py:186-188`
Scenario: `cv.py render ... --input lang=ΕΛ` on a Flagship workspace. Flagship ignores `lang`; the suite compiles with `lang=EN`.
Actual: `'ΕΛ'.lower()` passes `len == 2 and isalpha()`. The schema's `^[a-z]{2}$` then refuses it after `cv.pdf`, `render.json` and `checks.json` exist, which is M1's shape. I confirmed this in memory against `validate()`.
Fix: `lang if re.fullmatch('[a-z]{2}', lang) else None`.
