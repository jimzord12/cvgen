## Findings

### F1 Material: approved proposal still says "No web form"
Anchor: docs/proposals/client-workflow.md:33 and its Decisions section (lines 67-82)
Scenario: A later session checks the applicable decisions, as AGENTS.md requires, and reads "No web form: clients are not expected to be tech-savvy".
Expected: The owner's 2026-09-28 reversal is recorded as a dated Decisions entry, the same way that proposal already records the 2026-09-28 Text Draft change (docs/proposals/README.md, "Append brief dated entries for owner decisions").
Actual: Only the guide's parenthetical "(optional; owner, 2026-09-28)" records it, so the guide and the approved proposal contradict each other.
Fix: Append a one-line decision entry that quotes the owner. It is record-keeping, so it needs no round of its own.

### F2 Material: deletion promise not backed by the process; script project omitted
Anchor: docs/guides/client-workflow.md:88-89 and 246-247; scripts/intake-form.gs:20
Scenario: The consent text promises deletion 12 months after delivery. After some months the owner's Drive holds several forms that all have the same default title "Βιογραφικό: λίγες ερωτήσεις", plus "Untitled project" Apps Script projects. The per-client `FORM` blocks, especially follow-up ones built from the gap list, contain client facts.
Expected: At the delete-by date the owner can find and delete every Google artifact.
Actual: The guide says the form and Sheet "are deleted with the `Envelope`", but no step records the logged links in the Envelope `README.md`. The skill's delete-by check (SKILL.md:86-88) does not mention them. The Apps Script project is not named as something to delete. Only the Sheet carries the `Alias`.
Fix: Have the owner paste the three logged links (and the script project's link) into the Envelope `README.md`, or have Claude record them. Name the script project by `Alias`. Add "Apps Script project" to the deletion sentence and to the skill's delete-by report.

### F3 Minor: "you can change your answers after sending" overstates
Anchor: scripts/intake-form.gs:23 and 51
Scenario: Emails are not collected and there is no sign-in, so the only edit path is the "Edit your response" link on the confirmation page. A client who closes that page cannot edit. Edits made after the owner downloads the CSV are also silently missed.
Fix: Soften the sentence (for example, "use the Edit link on the last page") and have the owner download the CSV only when the client says they are done. I believe `setAllowResponseEdits` does not force sign-in on consumer accounts, but I did not check this against live Google documentation.

### F4 Minor: a follow-up form overwrites `intake/form.gs`, and the header says "once per client"
Anchor: scripts/intake-form.gs:12; docs/guides/client-workflow.md:196; SKILL.md step 7
Scenario: Step 7 reuses section 2, so Claude writes `intake/form.gs` a second time and loses the record of the first form. The script header forbids a second run per client, which contradicts that use.
Fix: Number the scripts `intake/form-NN.gs` to match `answers-NN.csv`, and change the header to "once per form".

### N1 Note: which tab to download; orphans on a late failure
`SpreadsheetApp.create` leaves an empty default tab next to the "Form Responses 1" tab. Sheets downloads only the current tab as CSV, so the guide should name the responses tab (I did not verify the tab order). If `setPublished` or `setDestination` throws, a form and Sheet already exist with nothing logged, so the "never leaves half a form" comment (line 68) applies only to `FORM` typos.
