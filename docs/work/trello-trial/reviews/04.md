### T4-01 Material: the failed request, Authorization header included, is also handed to a caller's `-ErrorVariable`; `$Error.RemoveAt(0)` does not reach it
Anchor: `C:\Users\jimzord12\Documents\GitHub\marine-engineer-cv\.claude\skills\trello\trello.ps1:65-72` (catch block); `:9` (`[CmdletBinding()]` advertises the common parameter); `SKILL.md:47-51`.
Scenario: `& $T GET cards/<stale-id> -ErrorVariable ev` (the standard way to capture a command's errors, and the natural next idea after SKILL.md says `2>&1` and `try/catch` see nothing), then `$ev | Get-Error` or `$ev | Format-List * -Force`.
Expected: no credential-bearing object left in caller state. Actual (fake credentials, byte-identical HEAD copy, `fake\H401-*`, `fake\HNR-*`, `fake\B-ev-fl.txt`): `$ev` receives two objects, the exception wrapper and the `ErrorRecord`; the record's `TargetObject` is the `HttpRequestMessage` with the full `Authorization: OAuth ...` header. `$ev | Get-Error` prints key and token twice each, `Format-List * -Force` once each, `.TargetObject.Headers` once; identical on the transport-failure path (fresh process with an unreachable proxy). Plain `$ev` is clean on those two paths. With a malformed token (CRLF) the FormatException message carries the raw header, so even plain `$ev` prints both values four times (`fake\H401-badtoken-ev-plain.txt`); the stderr line itself is redacted.
Impact: same class as T2-01 and T3-01, both accepted as Material in earlier rounds: the account-wide write token reachable from caller session state through a standard diagnostic. It is one step deeper than T3-01 (a capture parameter plus a deep print; the plain print is clean), which the lead may weigh, but I do not soften it.
Fix (two lines, verified on scratch copy `trello-r4-patched.ps1`, blob `5531d7b`): directly after `RemoveAt(0)` add `if ($_.TargetObject -is [System.Net.Http.HttpRequestMessage]) { $null = $_.TargetObject.Headers.Remove('Authorization') }`. The record in `$ev`, in `$Error`, and `Exception.Response.RequestMessage` all reference the same instance (`ReferenceEquals` True), so one scrub closes every holder: 0 hits under `Get-Error`, `fl * -Force` and `.TargetObject.Headers` on both paths, exits and messages unchanged (`fake\P401-*`, `fake\PNR-*`). Second line, after the missing-credentials check: `foreach ($v in @($key, $token)) { if ($v -notmatch '^[A-Za-z0-9_-]+$') { Fail '<clear message>' 2 } }`, so a malformed value exits 2 before any request exists (verified: exit 2, `$ev` empty, 0 hits) and replaces the mislabelled "no response ... format of value" message.
