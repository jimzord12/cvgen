## Findings

### T1-01 Blocking: helper prints the API key and token on any 4xx error
Anchor: `C:\Users\jimzord12\Documents\GitHub\marine-engineer-cv\.claude\skills\trello\trello.ps1:36-38` (credentials in the query string) and `:49-50` (response body printed verbatim).
Scenario: any call that Trello rejects with a path-level error, e.g. a mistyped endpoint or a stale/deleted card id (`GET cards/<old-id>` -> 404, an ordinary event in agent use).
Expected (SKILL.md "Credentials", proposal rev 2 "Keep tokens outside ... request logs"): the helper never prints them.
Actual: Trello's 404 body is `Cannot GET /1/<path>?key=<key>&token=<token>`; the helper puts `$_.ErrorDetails.Message` straight into `Write-Error`, so both credentials land on the console, therefore in the agent transcript and session log. Verified live with `GET nonexistent-path-for-review`. Because `$ErrorActionPreference='Stop'` turns `Write-Error` into a terminating error, the message escapes a caller's `2>$null` redirection (verified: my own suppressed check still printed both values).
Impact: the user token grants write access to the owner's whole Trello account, not just the trial board. Both values were printed in this review session and must be treated as compromised.
Fix (smallest): send credentials as a header instead of query parameters: `Authorization: OAuth oauth_consumer_key="<key>", oauth_token="<token>"` (verified 200 on `GET members/me` in this review); Trello's error bodies then cannot echo them. Belt and braces: in the catch, redact `$key` and `$token` from `$detail` and from `$_.Exception.Message` before printing. Then rotate: revoke the token (trello.com/my/account, Applications) and regenerate the API key (trello.com/power-ups/admin), and set the new values in the user-scope env vars.

### T1-02 Minor: `exit 1`/`exit 2` are unreachable; SKILL.md's "exit 1" contract is false
Anchor: `trello.ps1:27` with `:31-32`, `:50-51`, `:59-60`, `:90`; `SKILL.md` "Requests".
Under `$ErrorActionPreference='Stop'`, `Write-Error` throws, so `exit` never runs: after a failing call `$LASTEXITCODE` kept my sentinel value 777. Failure is still loud (terminating), so nothing is swallowed, but an agent checking `$LASTEXITCODE` reads a stale value. Fix: `[Console]::Error.WriteLine(...)` followed by `exit N`, or document "throws a terminating error" and drop the `exit` lines.

### T1-03 Minor: uncertain-create diagnostics are empty and there is no request timeout
Anchor: `trello.ps1:46-50`; SKILL.md "Uncertain create".
On a timeout/connection failure `$_.Exception.Response` is null, so the message is `... failed: HTTP  ` with no exception text (by reading; not exercised live). `Invoke-RestMethod` has no `-TimeoutSec`, documented default 0 = indefinite, so a hung POST blocks the tool call until the harness kills it, giving no message at all. The "list cards before retrying" rule still makes this safe if followed. Fix: `-TimeoutSec 30` and append `$_.Exception.Message` when `$status` is empty.

### T1-04 Note: export recipe overwrites and assumes the folder exists
Anchor: `recipes.md` "Export". `> builds/trello-<timestamp>/board.json` fails if the folder is missing and silently overwrites if it exists (constitution rule 2). Suggest `New-Item -ItemType Directory` + `Out-File -NoClobber` in the recipe.
